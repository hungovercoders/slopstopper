# Change map — every surface a change must touch

SlopStopper is a suite adopters install **and** a site that proves it
works, so one change usually lands in several places: the CLI, a
workflow, the installer, the config schema, the docs, the two Claude Code
skills and the site copy. This table is the checklist;
`cli/tests/test_check_registration.py` enforces the rows a test can, and
`ss:hygiene:docs-accuracy` catches drift between the layers.

| Change | Affects |
| ------ | ------- |
| Visual / brand | `app/shared.css` (tokens), then individual pages if they use new components |
| New quality check | Write `cli/slopstopper/checks/<module>.py` (a Playwright-backed check describes itself with a `_playwright.Check` and its `run()` is one call to `_playwright.run_check`, so smoke, e2e, accessibility and broken-links share the whole flow — copy `cli/slopstopper/checks/smoke.py`, not the plumbing), add workflow under `.github/workflows/ss-*.yml` (start from `.github/actions/ss-setup`; URL-driven → `ss-resolve-url`), add `task ss:<category>:<action>` target, add to `install.sh`'s `GENERIC_WORKFLOWS`, classify it in [`cli/slopstopper/data/profiles.json`](../../cli/slopstopper/data/profiles.json) (does it apply to an API? a library?) and map it in `profiles.CHECK_WORKFLOWS`, add a label to `badges.py`'s `WORKFLOW_DISPLAY`, add its `name:` to `ss-pr-summary.yml`'s `workflow_run.workflows` (no globs — an omitted name never re-renders the summary), pass `--status` on its `emit --target pr-comment` line, add a `DOC_HEADINGS` row in `cli/tests/test_check_registration.py` plus `cli/tests/checks/test_<module>.py`, document it under `docs/<category>/` and route the doc, add its `cli/slopstopper/checks/<module>.py` path under its category label in `.github/labeler.yml` (the workflow and docs globs there already match by prefix; the registration test fails until the module is listed), surface on `app/features.html` and `app/tools.html`, mention in `docs/runbooks/INSTALL.md`, **add to the skill duo**: workflow inventory + Pass A/B example in [`slopstopper-install`](../../.claude/skills/slopstopper-install/SKILL.md) (`.claude/skills/slopstopper-install/references/install.md`, `.claude/skills/slopstopper-install/references/verify.md`), reproduce row + gotcha row in [`slopstopper-triage`](../../.claude/skills/slopstopper-triage/SKILL.md) (`.claude/skills/slopstopper-triage/references/reproduce.md`, `.claude/skills/slopstopper-triage/references/gotchas.md`) |
| Renaming a `task ss:*` target or env var | `Taskfile.ss.yml`, `docs/<category>/README.md`, **both skills**: `slopstopper-install` (`.claude/skills/slopstopper-install/references/verify.md` local-task commands + aggregates, `.claude/skills/slopstopper-install/references/refresh.md` "Re-apply customizations"), `slopstopper-triage` (`.claude/skills/slopstopper-triage/references/reproduce.md`) |
| Editing `install.sh` (esp. `GENERIC_WORKFLOWS` or post-install stdout) | `install.sh` (the `REPO_URL` must always match this repo's actual location), `slopstopper-install` `.claude/skills/slopstopper-install/references/install.md` ("what it writes" lists + Step 3 inventory) |
| Changing the install/toolchain mechanism (mise vs pipx, `install.sh` prereqs, where the CLI pin lives) | The marketing + reference surfaces that describe how to install/upgrade — `app/index.html` (get-started), `app/tools.html`, `app/features.html` (workflow snippets), `cli/README.md` (PyPI front page), [`docs/architecture/README.md`](../architecture/README.md) (toolchain section + layout), `docs/runbooks/INSTALL.md`, `README.md`, **both skills**. `ss:hygiene:docs-accuracy` does NOT police the app's install copy, so this row is the guard — keep these in lockstep by hand |
| Editing a skill under `.claude/skills/slopstopper-*/` (map or `references/`) | [`install-skill.sh`](../../install-skill.sh) (installs `SKILL.md` + the `references/` it links — an unlinked reference never ships; adding or renaming a skill means its `SKILLS` array), [`docs/runbooks/INSTALL_SKILLS.md`](../runbooks/INSTALL_SKILLS.md), `README.md` "Docs" bullet, `app/index.html` "Claude Code users" section, the other skill's "When to hand off" pointer |
| Adding a new `slopstopper-*` skill | New `.claude/skills/<name>/SKILL.md`, `install-skill.sh` `SKILLS` array, `docs/runbooks/INSTALL_SKILLS.md` (trigger-table + What-lands + Uninstall), `README.md` link, `app/index.html` link, "When to hand off" pointers in each existing skill's closing section |
| Removing or renaming a slopstopper-shipped artefact (skill, workflow, template, check module) so adopter repos shouldn't carry it any more | Update `.github/labeler.yml` (a renamed path leaves a dead glob that actions/labeler never reports; the registration test catches a check module, nothing catches the rest). Add to the relevant obsolete-list so re-runs auto-clean it: skills → `OBSOLETE_SKILLS` in `install-skill.sh`; workflows or `.ss/` files → similar list in `install.sh` plus the existing byte-equality scrub if it moved into the CLI wheel. Then add a row to `slopstopper-install`'s "Clean up redundant artefacts" (`.claude/skills/slopstopper-install/references/refresh.md`) so the agent sanity-check covers it. The principle: adopter repos should hold only the expected set + their own customisations — anything else is noise to be flagged or auto-removed |
| Editing `install-skill.sh` (the one skill installer — `install.sh` runs it against its own checkout) | `docs/runbooks/INSTALL_SKILLS.md`, `README.md` + `app/index.html` if the install command line changes |
| Editing `.slopstopper.yml` schema (adding/renaming a key, changing a default) | [`.slopstopper.yml.example`](../../.slopstopper.yml.example) (the schema reference), [`templates/slopstopper.yml.starter`](../../templates/slopstopper.yml.starter) (the seed `install.sh` copies — its keys must stay a subset of the schema; a test checks), [`.slopstopper.yml`](../../.slopstopper.yml) (slopstopper.dev's own config), both skills reference the schema, the script that consumes the new key, `install.sh` if the new key drives installer behaviour |
| Adding or changing a project-shape profile (the `profile:` key) | [`cli/slopstopper/data/profiles.json`](../../cli/slopstopper/data/profiles.json) is the **single source of truth** for profile → workflow sets — the CLI reads it via `slopstopper.profiles`, `install.sh` imports that same module from the source tree, so never add a second copy of the mapping. Then: `.slopstopper.yml.example` (schema), `templates/slopstopper.yml.starter` (its `profile:` comment), [`docs/architecture/PROFILES.md`](../architecture/PROFILES.md), `install.sh` `--help`, `docs/runbooks/INSTALL.md`, `app/features.html` + `app/tools.html`, **both skills**. A new workflow must also be classified into every profile that should drop it |
| Adding a config-driven knob to a check (new `config.get("<x>")` call) | The check's module docstring (a Configuration block listing the keys it reads + defaults), `.slopstopper.yml.example` (schema; the starter too only if most repos set it), `slopstopper-install` (post-install "tunable knobs" pointer + Refresh-only "new knobs" section), `slopstopper-triage` (the "real / false-positive / threshold" branch should call out the config override) |
| Changing the AGENTS.md-first rules (what `ss:hygiene:entry-files` / `ss:hygiene:docs-structure` enforce, the route form, the budgets, or the entry-file scaffolds) | [`cli/slopstopper/checks/_routes.py`](../../cli/slopstopper/checks/_routes.py) (the route form + token estimate — one copy for both checks), [`cli/slopstopper/checks/entry_files.py`](../../cli/slopstopper/checks/entry_files.py) and [`cli/slopstopper/checks/docs_structure.py`](../../cli/slopstopper/checks/docs_structure.py) (rules + paste-ready snippets), [`cli/slopstopper/data/templates/entry-files/`](../../cli/slopstopper/data/templates/entry-files/) (the four scaffolds — keep them aligned with this repo's own `README.md` / `AGENTS.md` / `CLAUDE.md` / `docs/README.md`, the canonical examples; `cli/tests/test_entry_file_templates.py` runs the checks on them), `.slopstopper.yml.example` (the `entry_files` + `docs_structure` knobs), `install.sh` (`seed_template` calls), `slopstopper-install` Step 5 (`.claude/skills/slopstopper-install/references/map-pattern.md`) + Refresh-only knobs list, `slopstopper-triage` entry-files/docs-structure gotcha rows, `docs/hygiene/README.md` |
| Adding a new headers-source adapter | New module under [`cli/slopstopper/headers_adapters/`](../../cli/slopstopper/headers_adapters/), register in `__init__.py`'s `ADAPTERS` dict, add to the `format:` documentation in `.slopstopper.yml.example`, mention in `slopstopper-install` Step 1.5 and `slopstopper-triage`'s gotcha table |
| Editing a Playwright spec, `playwright.config.js`, or `lighthouserc{,.prod}.json` | **`cli/slopstopper/data/` is the only home** — adopter repos no longer carry these files by default; the CLI ships them inside the wheel and resolves `.ss/<filename>` first only if an adopter has explicitly overridden it. Edit under `cli/slopstopper/data/` and the change ships on the next `slopstopper-cli` release |
| New page | Add HTML + page-specific CSS in `app/`; link `app/shared.css` first; copy header/nav/footer; add to nav on the other pages; add to `tests/smoke.spec.ts` and `tests/accessibility.spec.ts` (under `cli/slopstopper/data/tests/`, per the row above) |
| Headers / CSP | `worker/headers.json` (single source of truth — CSP changes are blast-radius, touch DAST tests too) |
| Worker behaviour | `worker/index.ts` (path matching, redirects); `wrangler.jsonc` (assets binding, compatibility date) |

The right-hand column flags the skill duo wherever a change would drift either skill from reality — they name specific workflows, tasks and env vars, and silently rot if those change without them. Each skill's closing section carries the same instruction in the other direction.
