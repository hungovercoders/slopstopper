The suite

What the installer adds.

The CLI that runs the checks, the workflows that call it in CI, the task ss:* commands that call it anywhere, and the hook that runs the fast checks before a push.

🐍 slopstopper-cli

MIT

The Python package that runs each check, writes its report and posts the pull request comment. pipx install slopstopper-cli to try it; in a repo it is pinned in mise.toml. Each release carries its changelog and signed artifacts.

The commands 
slopstopper checks list                       # see what's available
    slopstopper doctor                            # verify external tools
    slopstopper run hygiene:docs-size             # run a check (writes .ss/reports/...)
    slopstopper emit hygiene:docs-size --target pr-comment
    slopstopper templates eject playwright.config.js
    slopstopper serve                              # bundled static server

Bare slopstopper prints the commands and a quick start. Every subcommand has examples in --help.

📋 Task

MIT

task ss:<loop>:<check> is how people, agents and CI all run a check, so there is one command to learn. Task is optional: install.sh --no-task has the workflows call the CLI directly.

Taskfile excerpt 
tasks:
  hygiene:docs-size:
    cmds: [slopstopper run hygiene:docs-size]
  reliability:accessibility:
    cmds: [slopstopper run reliability:accessibility -- "{{.CLI_ARGS}}"]

Run from your repo with task ss:hygiene:docs-size, task ss:reliability:accessibility -- https://example.com, etc.

🪝 Git hooks

GPL-2.0

A pre-push hook runs the static hygiene checks (task ss:hygiene:test) before every push; the browser and server checks stay in CI. It leaves an existing husky, lefthook or pre-commit setup alone. install.sh --no-hooks skips it, git push --no-verify bypasses one push.

.githooks/pre-push (installed) 
# Runs through `mise exec` because git hooks don't source your shell profile.
exec mise exec -- task ss:hygiene:test

The same command CI runs.

🕷️ OWASP ZAP

Apache-2.0

Dynamic scanning (DAST): probes the running deployment for XSS, injection and insecure headers. It spiders an HTML site, or exercises an API through its OpenAPI spec when api.openapi.spec names one.

The DAST check →
Workflow excerpt 
jobs:

    steps:
      - uses: actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803 # v6
      - uses: ./.github/actions/ss-setup
      - run: slopstopper serve &
      - run: task ss:security:dast -- http://localhost:8080

Reliability

The reliability tools.

A browser, an accessibility engine, a performance auditor, and four audits written in plain Python inside the CLI, so they add no dependencies.

🎭 Playwright

Apache-2.0

Runs the smoke, E2E, broken-link and accessibility checks against any URL. The specs ship inside the CLI; slopstopper templates eject copies one out to customise.

The E2E check →
playwright.config.js (bundled) 
export default defineConfig({
      testDir: './tests',                 // points at the bundled spec dir
      use: {
        baseURL: process.env.SMOKE_TEST_URL || 'http://localhost:8080',
      },
      projects: [{ name: 'chromium', use: { ...devices['Desktop Chrome'] } }],
    });
View cli/slopstopper/data/playwright.config.js →

Hygiene

The hygiene tools.

A complexity gauge and a seeded Markdown linter. The docs checks are plain Python inside the CLI and need no tool.

🐛 Lizard

MIT

Caps cyclomatic complexity per function across every language it parses. It ships with the CLI, so there is nothing to install.

The hygiene checks →
Workflow excerpt 
jobs:
      complexity:
        steps:
          - uses: ./.github/actions/ss-setup
          - run: task ss:hygiene:complexity   # fails above hygiene.complexity.max_ccn (15)
