Using slopstopper

The reference docs.

Each loop has a page per check: hygiene keeps code and docs readable to people and agents, security catches leaked secrets, unsafe code and vulnerable dependencies, and reliability proves the running site or API works for a visitor. The runbooks cover installing and updating; the architecture pages cover profiles, the pull request feedback and running the suite across an organisation.

What you do once around the suite: install it into a repo, install the Claude Code skills, move the CLI pin, and, for the project itself, cut a release.

Hygiene

The checks that keep code readable and docs true, for people and for agents: what each enforces, which setting tunes it, and how to fix what it finds.

  • Agentic Documentation UpdaterA weekly agent reads what merged, finds the docs that drifted from it, and opens a pull request with the fixes. It runs on GitHub Agentic Workflows (gh-aw) with the GitHub Copilot CLI engine.

Security

The security checks: what each one looks at, how it blocks, and where to tune it. One page per check; read the one whose trigger matches.

  • API Headers & CORSAudits a JSON API's response headers and CORS policy, where a permissive policy on a credentialed API is a cross-origin data leak.
  • CSP exceptionsThis file is the single source of truth for every per-path Content-Security-Policy relaxation on the SlopStopper site.
  • Dynamic Application Security Testing (DAST)OWASP ZAP scans your running site, or your API through its OpenAPI spec, for runtime security issues.
  • Licence Inventorysecurity:licences judges every dependency the lockfiles resolve to against the repo's licence allowlist, so a transitive package under a denied licence cannot sit in the tree unnoticed.
  • Static Application Security Testing (SAST)Semgrep scans your source code for security bugs and unsafe patterns before they merge.
  • Secrets DetectionGitleaks scans your source and your git history for committed credentials, API keys and other secrets.
  • Dependency Vulnerability ScanningTrivy scans your dependencies for known CVEs.

Reliability

The checks that prove the deployed site or API works for a visitor, each run against any reachable URL. Smoke, broken links, API health and API latency are covered below; seven more have a page each.

  • Accessibility Monitoringaxe-core audits every page against WCAG 2.1 AA, on every pull request, push to main and deploy, and daily.
  • Core Web Vitalsreliability:cwv runs Lighthouse CI against a URL and fails the build when a page's performance falls below budget. It is the browser-side speed check; API Latency is its analogue for a JSON API.
  • E2E JourneysThe E2E check proves a visitor can get around: it drives a browser through the journeys any HTML site offers, without knowing anything about yours.
  • llms.txt AI-Discoverability CheckAudits your site's /llms.txt, the llmstxt.org map that lets an AI assistant read your key pages without parsing HTML.
  • robots.txt Discoverability CheckAudits your site's /robots.txt: a stray Disallow: / that would de-index the whole site fails, and a Sitemap: pointer is required. /robots.txt is the Robots Exclusion Protocol file every crawler…
  • SEO & Social-Share Metatag CheckAsserts the tags a search engine and a link preview read on each page: title, description, canonical, OpenGraph and Twitter Card, with the share image reachable.
  • sitemap.xml Completeness + Drift CheckCrawls your site and cross-checks sitemap.xml against the pages it reaches: a reachable page missing from it, or an entry that 404s, fails.

Architecture

How the suite fits together: the CLI, the workflows and the task ss:* commands that call it, the toolchain, and the inner and outer loops the checks run in.

  • PR feedback: one summary, compact detailEvery pull request gets one summary comment, and a failing check adds a short comment of its own; this page is why, and the format of each.
  • Project-shape profilesA profile picks the checks that fit a repo's shape: ui for a website, api for a service with no pages, library for a package that serves nothing.
  • slopstopper-steward: the org-wide operatorslopstopper-steward works across a GitHub organisation: it upgrades every repo that has slopstopper installed and works the issues the checks raised, one pull request each.

Support

Where to ask a question, report a bug or request a check: an AI assistant first, then an issue on the repository, then a discussion.

Working with an agent

Let the agent install it and fix what it finds.

Two Claude Code skills ship with the suite: slopstopper-install adds the suite to a repo or refreshes it, and slopstopper-triage takes a red check from the workflow to the report to the fix. Installing the skills covers both; the steward runs them across every repo in an organisation. An assistant reading this site can start from llms.txt, which lists every page with a one-line summary.
