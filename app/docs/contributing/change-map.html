Change map: every surface a change must touch

  1. Docs
  2. Contributing
  3. Change map: every surface a change must touch

SlopStopper is a suite adopters install and a site that proves it works, so one change usually lands in several places: the CLI, a workflow, the installer, the config schema, the docs, the two Claude Code skills and the site copy. This table is the checklist; cli/tests/test_check_registration.py enforces the rows a test can, and ss:hygiene:docs-accuracy catches drift between the layers.

ChangeAffects
Visual / brandapp/shared.css (tokens: the light palette and the dark one, which is declared twice and must match), then individual pages if they use new components; docs/app/README.md's token table. A header change is all seven pages then task contributing:learn:site and task contributing:docs:site
New quality checkWrite cli/slopstopper/checks/<module>.py (copy cli/slopstopper/checks/smoke.py rather than the plumbing, because a Playwright-backed check describes itself with a _playwright.Check and its run() is one call to _playwright.run_check, so smoke, e2e, accessibility and broken-links share the whole flow), add workflow under .github/workflows/ss-*.yml (start from .github/actions/ss-setup; URL-driven → ss-resolve-url; Playwright-backed → npm ci then ss-playwright with timeout-minutes on the step, never an inlined npx playwright install), add task ss:<category>:<action> target, add to GENERIC_WORKFLOWS in cli/slopstopper/suite.py, classify it in cli/slopstopper/data/profiles.json (does it apply to an API? a library?) and map it in profiles.CHECK_WORKFLOWS, add a label to badges.py's WORKFLOW_DISPLAY, add its name: to ss-pr-summary.yml's workflow_run.workflows (no globs, and an omitted name never re-renders the summary), pass --status on its emit --target pr-comment line, add a DOC_HEADINGS row in cli/tests/test_check_registration.py plus cli/tests/checks/test_<module>.py, document it under docs/<category>/ and route the doc, run task contributing:tables (the category README's check table and the README badges are generated from the registry; cli/tests/test_check_tables.py fails while they are stale), add its cli/slopstopper/checks/<module>.py path under its category label in .github/labeler.yml (the workflow and docs globs there already match by prefix; the registration test fails until the module is listed), surface on app/features.html and app/tools.html, mention in docs/runbooks/INSTALL.md, add to the skill duo: workflow inventory + Pass A/B example in slopstopper-install (.claude/skills/slopstopper-install/references/install.md, .claude/skills/slopstopper-install/references/verify.md), reproduce row + gotcha row in slopstopper-triage (.claude/skills/slopstopper-triage/references/reproduce.md, .claude/skills/slopstopper-triage/references/gotchas.md). A URL-driven check with a url dispatch input also goes in the checks=(…) list of ss-cloudflare-deployed.yml, so Cloudflare repos run it after each deploy (a shape test enforces this)
Renaming a task ss:* target or env varTaskfile.ss.yml, docs/<category>/README.md, both skills: slopstopper-install (.claude/skills/slopstopper-install/references/verify.md local-task commands + aggregates, .claude/skills/slopstopper-install/references/refresh.md "Re-apply customizations"), slopstopper-triage (.claude/skills/slopstopper-triage/references/reproduce.md)
Editing the installer (cli/slopstopper/installer.py, cli/slopstopper/suite.py's GENERIC_WORKFLOWS or shipped set, the post-install stdout, or install.sh, the bootstrap that pins the CLI and hands over)A file the installer newly reads goes in suite.shipped_paths or the wheel will not carry it (cli/tests/test_suite.py builds the sdist and wheel to check); cli/tests/test_install_cli.py (what lands) and cli/tests/test_install.py (the pin and the hand-over); slopstopper-install .claude/skills/slopstopper-install/references/install.md ("what it writes" lists + Step 3 inventory)
Changing the install/toolchain mechanism (mise vs pipx, install.sh prereqs, where the CLI pin lives)The marketing + reference surfaces that describe how to install/upgrade, which are app/index.html (get-started), app/tools.html, app/features.html (workflow snippets), cli/README.md (PyPI front page), docs/architecture/README.md (toolchain section + layout), docs/runbooks/INSTALL.md, README.md, both skills. ss:hygiene:docs-accuracy does NOT police the app's install copy, so this row is the guard. Keep these in lockstep by hand
Adding a CLI subcommand (slopstopper <verb> …)cli/README.md's CLI surface block, cli.py's module docstring, and the doc for its area (docs/architecture/PROFILES.md for profile, docs/deployment/README.md for cloudflare, docs/architecture/PR_FEEDBACK.md for emit)
Editing a lesson under docs/learn/, or the syllabustask contributing:learn:site (the lesson's page under app/learn/ and the lesson entries in app/sitemap.xml and app/llms.txt; cli/tests/test_learn_site.py fails while they are stale) and task contributing:learn:tapes (its tape); a new lesson also needs its row in app/learn.html (cli/tests/test_learn_page.py checks) and in .slopstopper.yml's pages.* lists
Changing the site's header, nav or footerAll seven hand-written pages under app/ (there is no include), then task contributing:learn:site and task contributing:docs:site, which copy the Learn and Docs pages' chrome into every generated page
Editing a reference doc under docs/ (anything but a lesson), or adding, renaming or moving onetask contributing:docs:site (the doc's page under app/docs/, the section list on app/docs.html, and the doc entries in app/sitemap.xml and app/llms.txt; cli/tests/test_docs_site.py fails while they are stale, and the render fails on a relative link to a file that is not there or markdown outside the subset scripts/sitemd.py covers). A new or renamed doc also goes in .slopstopper.yml's pages.* lists (the same test checks); a new directory under docs/ needs a row in docsite.SECTIONS. A doc's page is the native target of the site's "learn more" links, so a path change here is a link change on the pages that point at it
Editing the demo repo (cli/slopstopper/data/demo/, what slopstopper demo writes)cli/tests/test_demo.py pins every deliberate finding and its fix, so a change that loses one or adds a second fails; cli/slopstopper/demo.py's FAILURES is what the command prints, keep it true; docs/contributing/FIXTURE.md describes the contents, which exclusion (.semgrepignore, hygiene.complexity.exclude) keeps a deliberate finding out of this repo's own runs, and why the fixture carries no secret and stores its vulnerable pin under a non-manifest name; anything that runs against it (a lesson, a tape, an eval) sees the change
Editing a skill under .claude/skills/slopstopper-*/ (map or references/)install-skill.sh (installs SKILL.md + the references/ it links, so an unlinked reference never ships; adding or renaming a skill means its SKILLS array), docs/runbooks/INSTALL_SKILLS.md, README.md "Docs" bullet, app/index.html "Claude Code users" section, the other skill's "When to hand off" pointer
Adding a new slopstopper-* skillNew .claude/skills/<name>/SKILL.md, install-skill.sh SKILLS array, docs/runbooks/INSTALL_SKILLS.md (trigger-table + What-lands + Uninstall), README.md link, app/index.html link, "When to hand off" pointers in each existing skill's closing section
Removing or renaming a slopstopper-shipped artefact (skill, workflow, template, check module) so adopter repos shouldn't carry it any moreUpdate .github/labeler.yml (a renamed path leaves a dead glob that actions/labeler never reports; the registration test catches a check module, nothing catches the rest). Add to the relevant obsolete-list so re-runs auto-clean it: skills → OBSOLETE_SKILLS in install-skill.sh; composite actions → OBSOLETE_ACTIONS in cli/slopstopper/suite.py; .ss/ files that moved into the wheel → the byte-equality scrub in installer.scrub_legacy_overlay. Then add a row to slopstopper-install's "Clean up redundant artefacts" (.claude/skills/slopstopper-install/references/refresh.md) so the agent sanity-check covers it. The principle is that adopter repos should hold only the expected set + their own customisations, and anything else is noise to be flagged or auto-removed
Editing install-skill.sh (the standalone skills refresher: it hands over to slopstopper install --only skills where a CLI is pinned, and fetches from main otherwise)docs/runbooks/INSTALL_SKILLS.md, README.md + app/index.html if the install command line changes
Editing .slopstopper.yml schema (adding/renaming a key, changing a default).slopstopper.yml.example (the schema reference), templates/slopstopper.yml.starter (the seed the installer copies, whose keys must stay a subset of the schema; a test checks), .slopstopper.yml (slopstopper.dev's own config), both skills reference the schema, the script that consumes the new key, cli/slopstopper/installer.py if the new key drives installer behaviour
Adding or changing a project-shape profile (the profile: key)cli/slopstopper/data/profiles.json is the single source of truth for profile → workflow sets. The CLI reads it via slopstopper.profiles, and slopstopper install resolves the workflow set through the same module, so never add a second copy of the mapping. Then: .slopstopper.yml.example (schema), templates/slopstopper.yml.starter (its profile: comment), docs/architecture/PROFILES.md, slopstopper install --help (in cli/slopstopper/cli.py), docs/runbooks/INSTALL.md, app/features.html + app/tools.html, both skills. A new workflow must also be classified into every profile that should drop it
Adding a config-driven knob to a check (new config.get("<x>") call)The check's module docstring (a Configuration block listing the keys it reads + defaults), .slopstopper.yml.example (schema; the starter too only if most repos set it), slopstopper-install (post-install "tunable knobs" pointer + Refresh-only "new knobs" section), slopstopper-triage (the "real / false-positive / threshold" branch should call out the config override)
Changing the AGENTS.md-first rules (what ss:hygiene:entry-files / ss:hygiene:docs-structure enforce, the route form, the budgets, or the entry-file scaffolds)cli/slopstopper/checks/_routes.py (one copy of the route form + token estimate, shared by both checks), cli/slopstopper/checks/entry_files.py and cli/slopstopper/checks/docs_structure.py (rules + paste-ready snippets), cli/slopstopper/data/templates/entry-files/ (the four scaffolds, which must stay aligned with this repo's own README.md / AGENTS.md / CLAUDE.md / docs/README.md, the canonical examples; cli/tests/test_entry_file_templates.py runs the checks on them), .slopstopper.yml.example (the entry_files + docs_structure knobs), install.sh (seed_template calls), slopstopper-install Step 5 (.claude/skills/slopstopper-install/references/map-pattern.md) + Refresh-only knobs list, slopstopper-triage entry-files/docs-structure gotcha rows, docs/hygiene/README.md
Adding a new headers-source adapterNew module under cli/slopstopper/headers_adapters/, register in __init__.py's ADAPTERS dict, add to the format: documentation in .slopstopper.yml.example, mention in slopstopper-install Step 1.5 and slopstopper-triage's gotcha table
Editing a Playwright spec, playwright.config.js, or lighthouserc{,.prod}.jsoncli/slopstopper/data/ is the only home. Adopter repos no longer carry these files by default; the CLI ships them inside the wheel and resolves .ss/<filename> first only if an adopter has explicitly overridden it. Edit under cli/slopstopper/data/ and the change ships on the next slopstopper-cli release
New pageAdd HTML + page-specific CSS in app/; link app/shared.css first; copy header/nav/footer (the footer carries the privacy line, so copy it whole); add to nav on the other pages; add it to the pages.* lists in .slopstopper.yml, app/sitemap.xml and app/llms.txt, and to the pages table in docs/app/README.md. A page about something docs/ already covers links the doc's page under app/docs/, never its file on GitHub
Headers / CSPworker/headers.json (single source of truth). CSP changes are blast-radius, so touch DAST tests too. A new allowed origin, embed, form or analytics snippet is also a change to app/privacy.html (which service, what leaves the site) and its "last checked" date, plus the footer line if what the site collects changes; ss:hygiene:privacy fails until the page names the new origin
Changing what a command prints: a check's stdout, doctor, profile, checks list or the bannerThe demo it appears in. demos/*.tape names the commands each one records; re-record with task contributing:demos (see DEMOS.md) and commit the GIF or PNG beside the tape. checks list and hygiene:entry-files also draw the site's app/assets/demo.svg and demo-dark.svg, one per theme: task contributing:shots redraws both
Worker behaviourworker/index.ts (path matching, redirects); wrangler.jsonc (assets binding, compatibility date)
Moving a surface slopstopper-steward reads: the "pipx:slopstopper-cli" key in mise.toml, .ss/.installed-from, the slopstopper repo topic, the slopstopper brand label and the slopstopper:check= / slopstopper:workflow= body markers in cli/slopstopper/emit.py, the workflow-failure label and ❌ Workflow Failure: title in ss-workflow-failure-issue.yml, the two skill directories, the ## Refresh-only heading in slopstopper-install/references/refresh.md and the slopstopper-workaround: marker, slopstopper install --no-topic, the run --json, checks list --json, profile expand <n> --json and doctor --json (needed_by) shapes, security:licences in cli/slopstopper/checks/__init__.py and its pip inspect in checks/licences.py, or the v<version> tag form (include-v-in-tag in release-please-config.json)docs/architecture/STEWARD.md lists why each is read. The steward's contract module pins the exact text and its CI checks it against main on every steward PR and nightly; nothing here does, so a rename here passes this repo's CI and goes red there within a day. Run steward contract <this checkout> from a steward checkout before merging, and open the matching steward PR in the same change
Fixing a bug an adopter reported and worked aroundClose the issue from the PR (Closes #N). Adopter repos carry slopstopper-workaround: hungovercoders/slopstopper#N markers on their workarounds, and slopstopper-install's refresh step removes a workaround once its issue is closed, so the issue number is the contract: never close one before the fix is in a release, and name the issue in the changelog entry so the refresh can check the pin against it. Both skills carry the marker convention (.claude/skills/slopstopper-triage/references/upstream.md, .claude/skills/slopstopper-install/references/refresh.md)

The right-hand column flags the skill duo wherever a change would drift either skill from reality, because they name specific workflows, tasks and env vars and silently rot if those change without them. Each skill's closing section carries the same instruction in the other direction.
