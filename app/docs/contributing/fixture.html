The demo repo

  1. Docs
  2. Contributing
  3. The demo repo

slopstopper demo writes a small fixture repository, shipped in the CLI wheel under cli/slopstopper/data/demo/, for anything that needs a repo to run slopstopper against with no network and no clone of this one: the course, the demo tapes, a triage walkthrough, the skill evals. It is "Lantern", a static status page, laid out the AGENTS.md-first way.

slopstopper demo                 # writes slopstopper-demo/
slopstopper demo --out /tmp/lantern --force
slopstopper demo --json          # {out, written, skipped, failures}

Files already in the directory are left alone unless --force is given, so a demo someone has started editing survives a second run.

The findings it must keep

One check per lesson fails on the fresh fixture, each with exactly one finding whose fix is the edit a real repo would make: a reader sees a red check, reads the report, fixes the real thing, and sees it green. Every other check passes or skips.

CheckFindingThe fix
hygiene:entry-filesREADME.md is over its 600-token budget (the manual under "Everything you need to know"); every rule passesMove that section into docs/ and route it; never raise the budget
hygiene:docs-structuredocs/runbooks/RELEASE.md has no routeOne row in docs/README.md: a trigger, then "read", then the link
hygiene:docs-accuracydocs/contributing.md says to run a task target (ss:hygiene:docs) and the repo has no TaskfileName the slopstopper run commands that exist
hygiene:complexitybadge() in scripts/status.py maps sixteen HTTP statuses with sixteen ifs: CCN 17 against the cap of 15A dict of the sixteen statuses and a one-line lookup, CCN 1
security:sastscripts/status.py builds a git commit command from a string and runs it with shell=True: subprocess-shell-true, at ERROR (two missing-integrity WARNINGs on the stylesheet links are reported and do not block)A list, and no shell
security:vulnerability:allscripts/requirements.txt pins requests==2.19.1: CVE-2018-18074 (HIGH), plus four MEDIUMs that are reported and do not blockThe version the Fixed In column names, or the current release
hygiene:csp-exceptionsapp/_headers lets /history.html load images from https://charts.example.com; the ledger has no entryThe entry with all seven fields, or drop the relaxation

The last three need the page served (slopstopper serve in the demo, then the check against http://localhost:8080). index.html passes every browser check on its own; smoke, e2e, broken-links, robots-txt and llms-txt pass on both pages, so a lesson that breaks one starts green.

cli/tests/test_demo.py runs every check on a written copy, asserts it reports its one finding and nothing else, applies the fix, and asserts green. The scanner-backed tests run the real tool and skip where it is not on PATH; the Playwright-backed tests skip without the repo's node_modules. slopstopper/demo.py's FAILURES is what the command prints after writing; keep it true to the fixture.

The fixture's slop and this repo's own checks

The fixture lives inside this repository, so two of its findings are excluded from slopstopper's own runs by path, with the reason beside the exclusion: .slopstopper.yml (hygiene.complexity.exclude) and .semgrepignore. The vulnerable pin is stored as scripts/requirements.demo and becomes requirements.txt only when the demo is written, so neither Trivy nor the dependency review reads it as ours. The fixture carries no secret: a key-shaped string in this repository's history would be found on every branch and reported to the vendor whose shape it borrows, so lesson 6 adds its own fake private key.

Changing it

Edit the files under cli/slopstopper/data/demo/ and run task contributing:test -- -k demo; a change that drops a finding, adds a second, or breaks a rule the fixture should pass fails there. A new finding is a row in FAILURES, a row in the table above, a test beside the others and, if this repo's own run would see it, an exclusion.
